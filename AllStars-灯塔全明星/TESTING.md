1. 导入 [dist/packages/bearcade.mcaddon](../dist/packages/bearcade.mcaddon)(全量),或分别导入

2. **行为包与资源包都必须启用**;
3. 改动后**完整重启世界**(`/reload` 对 JSON/UI 常无效);
4. `.env` 已配好(指向 `...\Users\Shared\games\com.mojang\development_*`),哪天路径问题修好即可恢复 `npm run deploy allstars`。

完成后会输出:三步各自的平均原始向量、结论(`axisMode` / `horizontalSign` / `depthSign`)、以及**可直接粘贴回 `combat-config.ts` 的值**。结果写入世界动态属性**持久化**(重启世界仍生效),同时立即生效,**无需重新构建部署**。

- 若某一步没检测到推杆、或前后与左右分不开 → 判**校准失败**并提示重试(不会写入脏数据);
- 想恢复默认:清掉该动态属性(键名见 `combat-config.ts` 的 `INPUT_CALIBRATION_KEY`);
- 校准后**立即**用下面的 probe 复核一次,确认"前推 depth>0、右推 horizontal>0"。

**复核路径:probe 打点(看原始值)**

```
/scriptevent allstars:probe        # 5 秒;依次做 前进/后退/左移/右移/跳跃/潜行,每次 0.5 秒
```

看内容日志里每行:
```
probe raw=(x 0.000, y 1.000) jump=Released sneak=Released |
derived(axisMode=x_horizontal) horizontal=0.00 depth=1.00 → jump=true crouch=false guard=false(…)
```

| 观察 | 结论 |
| --- | --- |
| **前推时 `raw.y` ≈ +1** | 默认 `INPUT_AXIS_MODE = "x_horizontal"` 正确 |
| **前推时 `raw.x` ≈ ±1 且 `raw.y`≈0** | 改成 `"y_horizontal"` |
| 左右推杆只改 `horizontal` 不改 `depth` | 轴映射正确 |
| 前后推杆恒为 0 | 按键兜底会接管(跳跃键→跳、潜行键→蹲),但仍建议查明 |
| 推离对手时 `guard=false`(预期 true) | 把 `GUARD_HORIZONTAL_BACK_SIGN` 改成 `1` |

相关常量(`combat-config.ts`):`INPUT_AXIS_MODE`、`INPUT_DEADZONE`、`INPUT_DEPTH_THRESHOLD`、`GUARD_HORIZONTAL_THRESHOLD`、`GUARD_HORIZONTAL_BACK_SIGN`、`INPUT_BUTTON_FALLBACK`。

## 六、已知限制(不是 bug,但有心理准备)

1. **判定粒度 50 ms**:游戏逻辑 20 tick/秒,而资产是 60 tick/秒。轻攻击真帧 active 折合**只有 1 个游戏 tick**,现按 `ACTIVE_WINDOW_MIN_TICKS = 2` 放宽为 2 tick。想更"帧准"要接受打不中。
2. **连段窗口从起手算**:可用余量 = `CHAIN_WINDOW_TICKS − 招式时长`(轻 23 / 重 17 / `_3` 重 15 tick)。
3. **连段不区分站姿**:空中轻击起手 → 落地后按轻击会接地面 `_2`(资产按 stand/crouch/air 分组,严格说不该跨组)。
4. **三气没有独立伤害结算**:为防同一发大招在 confirm/chain 阶段重复打一次,演出期间主动作废了起始段命中。
5. **KO 期间没钉住败者**:会带上一击的击退惯性滑约半格,特写焦点有轻微偏移。
6. **投技/发波是占位**:投技=近身高伤重击(无抓取/挣脱);发波按 `reach` 直接判定(**没有飞行物实体**)。
7. **无 hitstop/音效/粒子**:叶流粒子与残影资产还没接。
8. ~~跳格会连放技能~~ **已修(2026-09-25)**:技能键改成**边缘触发**(`playerHotbarSelectedSlotChange` 事件为主 + "槽位变化"轮询兜底),同一格持续按住只算一次;从第 1 格滚到第 7 格时中间经过的格仍会各触发一次(设计如此:一格一技能)。若仍嫌恼人,可按 6 tick 内的"连滚"只取最后一格 —— 等你实机反馈再定。
8b. **选中格延后回位（2026-09-26 最新）**：事件只记录输入；下一个游戏 tick 写 0，随后两 tick 再写，即使服务端已读到 0。选中 2～7 各格都应回第 1 格，失败出招/倒计时/硬直也如此；8、9 空格不干预。打开 `/bearcade:debug allstars enable` 可见 `快捷栏延后回位`；原生写入失败会独立输出 `快捷栏回位写入失败`。这些日志只证明服务端路径，必须同时看屏幕选中框，不能再把“读回 0”写成实机通过。
9. **输入缓冲对全部技能键生效**:包括大招(会真扣气)。标准格斗行为是"按键意图明确就执行",但如果你觉得"硬直结束瞬间自动放大招"太激进,可把缓冲限制为 1/2/3,或对 slot 6 单独关闭。
10. **防御期间横向移动是慢速**(0.6 倍):"背向对手推左右"既是防御也是后撤,所以两个效果同时生效。若希望防御**完全定身**(老手感),把 `GUARD_MOVE_SPEED_SCALE` 改成 0。
11. **HUD 文字宽度靠常量估**:TextPrimitive 的字符世界尺寸没有官方文档,现在按"血条 12 字符 + 6 空格 + 12 字符"配 `HUD_SCALE = 1`、`HUD_PLANE_DISTANCE = 4`。实机若看到血条被挤出画面两侧 → 调小 `HUD_SCALE`(或调大 `HUD_PLANE_DISTANCE`);若太小看不清 → 反向调。
12. **击倒只有一条路径**:投技摔倒与连打倒地共用 `beginKnockdown()`,差别只在进入动画(`throw_victim` / `knockdown`)与时长;倒地期间**免疫伤害**(防止贴脸锁死),想要"倒地可追击"就把 `KNOCKDOWN_INVULNERABLE` 改成 false。
13. **跳跃整体变高了**(顶点 3.2 格才能过对手):觉得"太飘"就同时调 `JUMP_VELOCITY` 与 `GRAVITY_PER_TICK` —— 注意顶点必须 > 2.9 格,否则又跳不过去了。`diag` 会直接把顶点/滞空/横移算给你看。
14. **后台是地板下的暗格**:玩家本体(隐身)站在擂台地板下方的小平台上,所以"本体不在场地里"。旧存档没重建场地时会**自愈**补一块 5×5 平台(内容日志会提示重跑 buildmap);选人阶段的画面由 `camera.preview()` 给出,与本体位置无关。
15. **突进没有无敌帧/冷却**:双击窗口 0.4 s、推过 0.6 才算一次;突进期间锁普通操作(这期间按的技能键会进输入缓冲,冲刺结束自动起手)。要 i-frame 或冷却再说。
16. **开场运镜只在第一局**:第 2 局起是 30 tick 的准备停顿 —— 否则每局都要等 6.5 s。
17. **浮空字颜色属于文字内容**:TextPrimitive 的位置、缩放、背景等属性保持既有方案；P1/P2 颜色码写入共享文字，双方视角固定为 P1 蓝色、P2 红色，低血量一侧为黄色，不按观察者身份反转。
18. **重受击区分**:重攻击/投技/大招(3/4/6)命中站立目标时播 `hit_stand_heavy`,其余走 `hit_stand/crouch/air`。
19. **拆投判定是"双方都在投技起手窗口内"**(默认 6 tick),不是帧级拆投,也没有"拆投失败"分支。
20. **三气首击的"确认"用距离 + 非防御判定**(不是逐帧命中检测):超距或被挡即走 `super_3_whiff`。
21. **俯冲/上挑是脚本位移**(不是引擎物理):俯冲额外下坠、上挑把本体抬起 2 格左右;数值全在 `combat-config.ts`(`LEAF_DIVE_*` / `LEAF_RISE_*`),嫌冲太远/抬太高就调它们。
22. **`*_victim` 只由命中确认触发**:被防御、落空、三气首击未确认时受击者不播任何配对动画 —— 这是规格明确要求的行为,不是遗漏。
23. **道具是独立实体 + 近似挂点**:珍珠/命令方块来自源资产 `props/`,源资产里它们是"挂在手骨上的预览道具",Bedrock 侧只能每 tick 传送到按偏移估出的"手"位置。所以高速移动/出招时道具可能有几十毫秒的跟随延迟;要做到帧级贴合需要把道具**烘进角色几何**(让模型作者把珍珠/方块作为骨骼加进 geo 并重导动画)—— 这条我做不了,要改就得动模型。
24. **2026-09-26 最新残影结论**：半透明 PNG 和随后仅有 0/255 alpha 的像素溶解都被用户反馈为丢贴图，现停用这两种过渡。人物和残影只引用两套原皮肤，瞬移仅使用布尔显示/隐藏。检查前后冲、三气和整场胜利，确保恢复时是原皮肤；不能将本版描述成半透明渐变。

### 最新四项实机复核

- 珍珠：旧日志报道具动画加载失败、找不到 `size`，本版改走客户端 `scripts.scale`。先运行 `/bearcade:allstars_diag`，在第 2～6 秒观察缓慢缩小再放大；随后看对局中 0.15 秒的快速缩放。二气框和珍珠时钟仍随定帧/慢放，模型和框体是否穿模需要客户端观察。
- 气条：0.5 显示 0 气 +50%，1.0 显示 1 气 +0%，1.5 显示 1 气 +50%，2.0 显示 2 气 +0%，3.0 显示 3 气 +MAX。两位玩家分别显示自己的数值。
- 第 7 格：满三气时，单按 7 必须只放一气并剩二气；W+7 放二气并剩一气；S+7 放三气并归零。分别在不足一/二/三气时尝试对应组合，应拒绝且不降档、不扣气；2.4 气放二气剩 0.4。W+7 同 tick 不先跳，缓冲期间松开方向不能改档；两侧都测试。
- 二气命中显示围住对手的空间框，随后倾转、收窄、消失；格挡/落空不应有框。换局/离开对局后没有残留道具。
25. **拆投窗口 2 游戏 tick**:源资产 `techWindow=[21,27)` 是**制作 tick**(60/秒)= 0.1 秒,别再按"6 个制作 tick = 6 个游戏 tick"换算。
26. **0.1 倍速做不出来**:规格里 KO 的 `ko.rate = 0.1` 要的是**动画播放倍率**,而 `Entity.playAnimation()` **没有 speed 参数**(当前版本)。所以强慢放用"撞击定帧 + 拉长停顿 + 特写运镜"近似。**要做到真 0.1 倍速**,要么让模型作者烘一版"慢速 KO 动画"(把同一段动作铺到 10 倍时长),要么改用客户端 animation controller + Molang 速度变量控制 —— 后者要重构整套动画驱动方式,不建议现在做。
