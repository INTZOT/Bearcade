## 血量、伤害与连招补正（2026-09-27）

双方脚本战斗血量为 **10000 HP**，HUD 自动按新上限显示；低血量门槛为 **≤2500 HP**。以下是未补正、未防御且目标血量足够时的伤害：

| 春叶招式 | 基础伤害 | 连招中整招最低伤害 |
| --- | ---: | ---: |
| 轻攻击（站/蹲/空三段，每段） | 300 | — |
| 中攻击（站/蹲/空三段，每段） | 600 | — |
| 重攻击（站/蹲/空三段，每段） | 850 | — |
| 投技 | 1200 | — |
| 站立发波 | 650 | — |
| 升龙（S+6） | 1400 | — |
| 空中俯冲（空中6） | 800 | — |
| 一气 SA1 | 2000 | 600（30%） |
| 二气 SA2 | 2800 | 1120（40%） |
| 三气 SA3 | 4000 | 2000（50%） |
| 残血三气 CA | 4500 | 2250（50%） |

三气前七击为 **500 / 300 / 300 / 350 / 350 / 350 / 350**；普通终结为 **1500**，残血终结为 **2000**。残血分支仍在接受释放时锁定；前七击最低留 1 HP，只有终结接触可以 KO。

全角色共用 `src/damage.ts`：普通起手补正依次为 **100% → 100% → 80% → 70% → 60% → 50% → 40% → 30% → 20% → 10%**，之后维持 10%。轻起手跳过第二个 100%，即 **100% → 80% → 70%…→10%**。重起手第一击仍为 850，后续在普通序列上额外乘 80%，即 **100% → 80% → 64% → 56%…→8%**；大招保底取更高者。

大招在命中/捕获确认时锁定整招补正，再把补正后的总额分给各次接触，所以裸放三气不会自己衰减。三气八次接触占用八个后续连招档位。普通伤害向下取整，多段大招的整数余数交给终结，保证总额准确。投技和二气在捕获时锁定补正、实际冲击帧扣血一次。

补正在受击者恢复行动、起身完成、拆投或换局时重置；防御、无敌挡下、挥空不累计。时停/慢放/配对演出不会使补正超时重置。这与原有“三段按键窗口”“五连击倒地计数”分别维护。防御削血按旧血量比例换算为新单位（重攻击 200、大招 800；原本为零的仍为零），不计入命中连招。

角色伤害配置在 `src/data/chunye.damage.ts`，通用补正与 SA 保底在 `src/damage.ts`；后续角色应提供自身基础伤害并复用 `Fighter.confirmDamage()`，延迟/多段伤害不得绕开它或在扣血帧重复补正。

## 起身、对抗与技能节奏（2026-09-27 最新）

- 大招受击者按实际扣血积攒气：每损失 5000 HP 获得 1 气，上限 3。裸吃 SA1/SA2/SA3/CA 分别获得 0.4/0.56/0.8/0.9 气；补正、剩余血量不足会相应减少。三气每次接触即时累加，捕获、停顿、恢复帧不重复给气。普通受击和防御攒气沿用原规则。
- 倒地全程不可被追加命中；起身结束先更新状态再读输入，保留 8 tick 按键缓冲。起身后 **4 个游戏 tick（0.2 秒）无敌**，期间可反击、移动或防御，挡普通攻击与投技；三气确认也不能绕过保护。它是起身无敌，不代表每一种慢招都能保证反打。
- **升龙对升龙、升龙对俯冲：实际接触时后发者获胜**，只结算后发招式一次伤害（升龙 1400、俯冲 800，仍受连招补正）。后发者仅对正在对抗的旧升龙/俯冲有起手保护，进入接触范围后最早 2 tick 可反击；普通拳脚、投技和独立飞行波仍能打断。专用对抗垂直范围为 3.2 格，普通升龙仍为 1.9 格水平/2.2 格垂直。同 tick 没有后发者，双方抵消无伤，不能由 1P 顺序定胜负。
- 升龙最后一个 loop 结束后关闭攻击判定，留 **10 tick（0.5 秒）收招**；空中依然能被正常对空攻击。这给避开升龙的对手一个惩罚窗口。
- 三种发波共用 **28 tick（1.4 秒）的起手间隔**，从成功出招算起；普通波 20 tick 收招后额外等待 8 tick，等待中能出拳、投或移动。升龙/俯冲自身动作未结束时仍需先收招。换站姿不能绕过 CD，换局清零；时停和命中停顿暂停 CD。
- 俯冲命中：自己 6 tick 收势、对方 12 tick 受击硬直，减少水平击退并停止继续俯冲，支持接轻攻击；被防御时沿用防御硬直。命中停顿暂停按键缓冲，避免预输入过早丢失。
- 投技仍是近身普通投：保留 7 tick（0.35 秒）前摇、1.5 格范围、1.4 秒摔落和 2.6 秒起身节奏。**双方同 tick 已进入有效判定时，有效抓取先于普通打击**；前摇期间仍会输给快拳，跳起/超距/起身无敌可躲投。拆投仍为捕获附近 2 tick 窗口。
- 二气新增 **朝对手的左右方向＋7**，兼容 W+7；S+7 优先三气，单按 7 一气，耗气不变。按下时记录方向，两边换位后按当前朝向解释，缓冲中松开方向不改变档位。
- **三气进入抓取区就确认**：高抛后保留 0.875 倍追击时钟、0.55 格/tick 水平速度，最多追击约 0.9 秒。每 tick 检查原有抓取区（水平 ≤2.4 格、高差 <1.8 格）；提前到达即跳过剩余追击，从原作者 t114 完整播放首拳蓄力和后续演出。先结算本 tick 对手有效攻击/投技，被打断则不能确认；倒地、无敌、高空目标仍不能强抓。最大追击距离、起跳规则、无敌和首拳破防保留，本轮只改确认时机。
- **一气短突进与拳击特写**：最大位移由旧 22/16 格改为 **2.5 格**，贴近时提前停在对手身前约 1.1 格。珍珠、相机和本体共享落点，实体必须真正到达再判拳，拳击水平距离仍为 1.65 格，落点外目标不受伤。起手速度保持 1.5 倍。防御窗口只在位移阶段开放：位移期间已进入防御的目标可以挡住一气；蓄力慢镜头开始后才新进入防御无效。释放时以 0.25 秒平滑进入侧前方拳击特写，接触停顿期间保持机位，作者 t28 后平滑拉回原侧视镜头看受击退倒；被防住、落空或中断也恢复，KO 由既有 KO 特写优先接管。

以上时间均为 20 tick/秒的游戏时间；模型作者帧仍为 60 tick/秒。本轮不改原生 86 段骨骼资产。

## 操作方式(玩家侧)

两名玩家人体**不在场地内且隐形**,擂台上的角色由自定义实体扮演;所以操作方式是"**行动检测 + 重定向**":

| 玩家动作 | 角色行为 | 动画 |
| --- | --- | --- |
| 左 / 右 | 左右移动(**绝对屏幕方向**:推左=屏幕左移,推右=屏幕右移) | `walk_forward` / `walk_backward` |
| 朝屏幕上方推(前) | **跳跃**(仅在地面;空中无效);顶点约 3.2 格 ⇒ 可以**从对手头顶跳过去** | `jump_start` → `air_rise` / `air_fall` → `jump_land` |
| 朝屏幕下方拉(后,按住) | **下蹲** | `crouch_enter` → `idle_crouch` → `crouch_exit` |
| 按住**背向对手**的左右方向；同时下蹲则蹲防 | **防御姿态**(站立防 / 下蹲防),**期间仍可慢速横向移动**；单独下蹲不防御 | `guard_hit_stand` / `guard_hit_crouch` → `guard_stand` / `guard_crouch` |
| **连续两次左左 / 右右** | **突进(冲刺)**:朝对手方向 ⇒ `dash_forward`,背离对手 ⇒ `dash_backward`;位移约 3.5 格 | `dash_forward` / `dash_backward` |
| 切换快捷栏格 | 释放对应技能,**随后自动切回第 1 格** | 见下表 |

> **帧约定(2026-09-25 实机修正)**:两名玩家共用**同一台侧视相机**,输入向量表达的是摇杆自身朝向,所以对双方都是**绝对屏幕方向**映射(以前按 `facing` 翻转 ⇒ P2 前推变蹲、右推变左移)。`facing` 只用于判断"防御 = 按住背向对手的方向"与"突进该播 forward 还是 backward"。
> **双击突进**:只认**边缘**(推过 `DASH_TAP_THRESHOLD = 0.6` 才算一次),两次落在 `DASH_DOUBLE_TAP_TICKS = 8`(0.4s)内触发;用掉后清记录,三击不会连冲。
> 技能键是**边缘触发**:主用 `world.afterEvents.playerHotbarSelectedSlotChange`,事件不可用时退回"槽位变化"轮询 —— 同一格持续按住只算一次(旧实现每 tick 读一次会把同一格当成连按)。
> **选中格回位**：选中事件只记录输入与方向；后续 tick 写回第 1 格并补两次写入。针对“逻辑已回 1、选中框仍停在技能格”的新反馈，最后一次写回后仅隐藏原生快捷栏 1 游戏 tick，再恢复显示，尝试刷新旧高亮。可能有约 0.05 秒闪动，实际效果待客户端验收；不改其它 HUD 可见性，清场也会恢复本轮隐藏的快捷栏。服务端读回 0 仍不能证明客户端选中框回位。

| --- | --- | --- |
| 1 | (空手,默认格) | — |
| 2 | 轻攻击 | `attack_{stand,crouch,air}_light(_2/_3)` |
| 3 | 中攻击 | `attack_{stand,crouch,air}_medium(_2/_3)` |
| 4 | 重攻击 | `attack_{stand,crouch,air}_heavy(_2/_3)` |

## 道具(末影珍珠 / 命令方块)

源资产 `source/v047/props/` 里有两个**独立道具**模型(不是角色骨骼 —— 角色动画 JSON 里完全没有它们的通道,预览器里是"挂在手骨上的道具"),由 [scripts/allstars-ingest-props.mjs](../scripts/allstars-ingest-props.mjs) 接入为**独立实体**,运行时每 tick 传送到"手"的位置:

| 道具 | 实体 | 出现时机(源资产规格) |
| --- | --- | --- |
| 末影珍珠 `geometry.green_beret.ender_pearl` | `bearcade:allstars_prop_pearl` | ① **开场**:双手中生成,末段移到右手并收进(`intro.pearlGather`);② **冲刺**:挂右手,**第 2 tick 释放**后独立飞向突进终点(`dash.release`);③ **一气**:聚珠后甩出(`super_1.pearlGather`);④ **三气**:每段抛一颗飞向对手(`super_3` 珍珠链) |
| 命令方块 `geometry.green_beret.command_block` | `bearcade:allstars_prop_command_block` | **二气**整段:双手上下夹住方块 → 转身 → 压缩 → 砸地(`super_2.prop`,`propVisible=[8,124]` 制作tick ≈ 3~41 游戏 tick) |

- 尺寸：珍珠 ×1.5；命令方块由 ×2.2 缩为 ×1.1，边长减半。统一调整 `scripts/allstars-visual-assets.mjs` 中的 `PROP_SCALES`，build 和重新导入均会写入实体 JSON。
- 珍珠/命令方块出现和消失：各用 3 游戏 tick（0.15 秒）缩放，由 client entity 的 `scripts.scale` 读取 `bearcade:prop_scale`，共用所属房间的时停/慢放时钟。`/bearcade:allstars_diag` 中两种道具都会在第 2～6 秒慢速缩小再放大；换局等清场立即移除。命令方块与二气包围框是不同实体，这里缩小的是手中的方块。
- 二气空间框：成功捕获后的第 36～140 制作 tick 显示独立的细线立体框，随对手定位；52～84 倾转、118～124 压缩、130～140 收拢消失。格挡/落空不生成。资产生成器为 `scripts/allstars-prop-assets.mjs`，参考原 v034 `super_preview.html`。

- 道具是**纯表现**:任何一步失败都静默,不影响伤害/回合;换局与清场一律 `despawnAllProps()` 收干净。
- `diag` 里有一条**道具探针**(眼前生成珍珠 + 命令方块,12 秒后清除),用来确认模型有没有加载。

**击倒规则**:① 投技命中 → **把对手摔倒在地**;② 连续命中 5 下(期间没断)→ **把对手打倒地**。倒地会播 `knockdown`/`throw_victim` → `idle_down` → `getup`,期间锁输入并免疫伤害。常量在 `combat-config.ts` 的 `THROW_KNOCKDOWN*` / `KNOCKDOWN_*` / `COMBO_RESET_TICKS`。

## 系统

- **玩家本体不在场地里**(规格):玩家原来的角色被隐身、每 tick 拉回**擂台地板下方的后台小平台**(`BACKSTAGE_*`),场地内只有前台角色实体。玩家看到的画面完全来自脚本下发的 free 侧视相机 —— 包括**选人阶段**的固定取景(`SideCamera.preview()`),否则玩家会盯着后台的墙。旧场地没重建时会**自愈**补一块平台。
- **血量/气**:双方 10000 HP;气条记录命中/受击积累的 0~3 气。单按 7 / W+7 / S+7 分别选择一气/二气/三气，并支付对应 1/2/3 气；气不足时拒绝该档位且不自动降档。起身完成后另有 2 游戏 tick 无敌，避免压起身。
- **自动转向**:角色每 tick 按双方实际左右关系转向对手(越过对手后会转身);出招/冲刺/硬直/倒地期间锁定朝向(源资产 `integration.facing` 要求"动作开始即锁朝向")。
- **打击感三分工(源资产 `ownership.presentation`)**:
  ① **释放时停**(一/二气):双方冻结 `SUPER_FREEZE_TICKS = 8`（0.4 秒）,施法者气场时钟独立推进(动画继续);
  ② **命中定帧**(hitstop,**所有命中都有**,越重越长):轻 2 / 中 3 / 重 5 / 投 5 / 发波 3 tick,大招按气量 4/8/7,被防御 2 —— 定帧期间**双方 + 相机一起顿住**(位移/击退/垂直物理全停,动画继续播),这就是"打到那一下顿住";
  ③ **强慢放只在 KO**：在最终有效接触时立即硬切特写、显示中央 KO，先定格 10 游戏 tick（0.5 秒），再用共享动作时钟按 0.1 倍速推进 8 作者 tick（约 1.35 秒墙钟）。三气前七击仍保留 1 HP；KO 阶段继续推进最后一击的配对收尾。不会把整套演出播完后才开始慢放。
- **KO / 结算演出**:打出 KO 后败者**持续躺地**(`idle_down` 循环,直到下一局重新站好),胜者播胜利动画;KO 阶段与结算阶段不跑对局逻辑,但由 `Fighter.tickPresentation()` 单独推进动画(否则倒地动画会卡在最后一帧)。
- **回合**:三局两胜;单局 99 秒(可配),血量归零或超时血少者负。
- **开局运镜与倒计时**：第一局依次展示两名角色，每人 `INTRO_CAMERA_TICKS = 66` 游戏 tick（3.3 秒），随后拉回双方同框机位并显示 **3 → 2 → 1 → 开打!**。每个数字持续 20 游戏 tick，总计 `ROUND_INTRO_TICKS = 60`。第 2 局起直接倒计时，不重播开场动作；倒计时期间不接受战斗输入，99 秒回合计时从开打开始。
- **中央提示与瞬移**：保留原有四个 TextPrimitive HUD。瞬移改为二值隐藏模型，离开／到达时使用末影粒子和珍珠爆点；不再生成可见残影，不使用半透明皮肤。一气抛珠后最多前移 2.5 格、到达后出拳，近身时保留 1.1 格间距。瞬移隐藏不额外赋予无敌。
- **气条与大招操作**：气条旁显示 0/1/2/3 气，条内显示到下一气的进度与百分比；满 3 气显示 MAX。**单按第 7 格放一气，朝对手方向+7 或 W（跳跃方向）+7 放二气，S（下蹲方向）+7 放三气**；接受释放时分别支付 1/2/3 气，不足时拒绝且不降档，按键事件记录当时方向，硬直缓冲中松开 W/S 不会改档。同 tick 的 W+7 优先大招，不先起跳；提前按住 W 已起跳时仍遵守现有空中施放规则。三气低血分支仍在释放时按 ≤25% HP 锁定。
- **胜利演出**：KO 慢放结束后，空中胜者先保持 `air_fall` 下落；胜利动作只在真实落地并播完 `jump_land` 后开始。败者模型在进入结算时退出场地，下局恢复。短胜利用正面全身镜头；整场胜利采用 v043 预览的开场／空间穿梭／最终指向镜头三个构图，切段硬切、段内小幅运镜。整场胜利作者 tick 124–220 以 0.65 倍速播放，整体约 6.45 秒后接待机；等待落地和放慢增加的时间均不挤占结算展示时长。
- **位移发波的叶流**：S+6 升龙和空中 6 俯冲不再复用站立水平波。每个移动 tick 按人物实际世界位移计算方向，持续补发叶片（每侧单独节流）；升龙从沿轨迹反投的地面位置补出叶流，俯冲朝前下方飞行、按落地点限制粒子寿命。俯冲水平速度为 0.48 格/游戏 tick，比此前 0.32 增加 50%；下坠参数保持，命中或真实落地后停止水平俯冲。
- **本轮判定收窄**：站立波的逻辑命中窗口与视觉射程分离，垂直容差为 0.9 格、扫过缓冲为 0.22 格、逻辑命中射程为 17.5 格；叶流视觉距离不变。S+6 升龙使用 1.9 格水平、2.2 格垂直的独立命中窗口，避免在高点仍宽范围命中地面目标。
- **投技共享动作时钟**：捕获后施放者与受击者按同一投技时钟校准，绝对冲击节点为按下后约 28 游戏 tick（1.4 秒），随后保持躺地并在约 52 游戏 tick（2.6 秒）进入起身完成；定帧或演出切段不会再让一方提前落地。
- **三气起手权限**：聚珠与抬头抛珠阶段锁定对手的移动、攻击和防御输入；进入珍珠瞬移追击窗口（作者 tick 69–114）后重新允许对手操作；首击确认后再次锁定双方进入配对演出。施放者起手有 3 游戏 tick 的短暂无敌，首击确认前 3 制作 tick 允许破防。落空或被打断会恢复权限。
- **相机**:沿双方**中点的中垂线**取顶点侧视。**FOV 固定 62°**,画面远近只由**机位距离**决定 —— 机位距离由"装下两人 + 余量"的取景需求反解(`CAMERA_FRAME_HALF_HEIGHT`,默认约 11 格,旧实现只有 3.5~6 格,实机反馈"太近"已修);两人拉开到超过 `CAMERA_MAX_DISTANCE` 时才用 FOV 补足。**平滑**:目标位姿先做指数平滑(`CAMERA_SMOOTHING`),再节流下发(`CAMERA_UPDATE_TICKS = 2`)且 `easeTime ≈ 节流间隔 + Linear` ⇒ 首尾相接的匀速运镜;换局/从 KO 特写回位走 `force`(目标吸附 + 0.5 s `InOutSine` 长缓动)。实现约束(实测):自定义相机预设在本版本**不加载**、`follow_orbit` 半径**锁死 10**,所以位置只能用 `minecraft:free` + `easeOptions`。
- **HUD**：平时保留透明实体锚点与原有四个 TextPrimitive 血条／气条／信息／大字形状及布局。大招、KO、胜利演出期间隐藏前三行，结束后恢复，禁止切换到 title HUD。开场仅在 actionbar 显示带席位色的操控信息。KO 大字仍是第 4 个 TextPrimitive，但临时解除实体附着，按真实特写镜头直接放在屏幕中心。另有两个独立 TextPrimitive 绑定角色动画头顶，双方都看到蓝色 `1P`／红色 `2P`；瞬移隐藏或退出场地时一同隐藏。
- **HUD 颜色**：HP ≤25% 时对应血条变黄；只有同一侧同时残血且达到 3 气时，对应气条变黄。其余情况下 P1 固定蓝色、P2 固定红色，双方视角一致。
- **对局结束的复位契约**:清 HUD → `camera.clear()` + `stopShaking()`(**绝不在 clear 之后再 setFov**,否则会把玩家自己的视野设置永久顶掉)→ 角色实体 → 输入权限/隐身/笼 → 快捷栏;`onBeforeReset` 还会对房间里残留的玩家再兜底复位一次相机。
- **血量显示与三气排查**：平时血条外侧显示具体 HP，演出时隐藏 HUD 但伤害正常结算。三气结束在日志输出“8/8 击、实际扣血、HP 前后值”；无前置连招时普通三气对满血为 10000→6000，残血三气为 10000→5500。数值、完整收尾和 P1/P2 镜头投影已做自动回归，客户端观感仍需实机验收。

## 相机与输入的实测前提(重要)

- `player.inputInfo.getMovementVector()` 的 **x/y 轴语义官方未定义**,仓库也从未用过。因此 `combat-config.ts` 留有 `INPUT_AXIS_MODE` 开关,并提供调试命令实测:
  - `/scriptevent allstars:probe` —— 对自己打印 5 秒内的原始输入向量与按钮状态。
  - **实测结论(2026-09-25)**:`x_horizontal`;`horizontalSign = -1`(右推 raw.x ≈ −0.86,该轴"左正")、`depthSign = +1`(前推 raw.y = +1.00)。这组值已写成 `combat-config.ts` 的默认值,并存进世界动态属性;`/bearcade:allstars_calibrate` 可随时重测覆盖。
  - 复核一句话:**推右 ⇒ 角色朝屏幕右走;推前 ⇒ 起跳;推后按住 ⇒ 下蹲**。任一条不对就重跑校准(推到底、全程不松手)。
- `InputButton` 枚举**只有 `Jump` / `Sneak`**(没有攻击/方向按钮),所以方向输入只能靠上述轮询。
- `Entity.playAnimation()` **不能在 restricted execution 中调用**,所有动画调用都在 `system.runInterval` 回调里。

## 实现进度

**已实现(M2-a / M2-b,可实机验收)**

1. **一二气释放时停**:释放瞬间对对手 `inputPermissions(Movement,false)` + 每 tick `clearVelocity()` + 喂空输入(逻辑时钟暂停),施法者不受影响(气场时钟独立);表现用 `camera.fade` 白闪 + 震屏。**未使用 `/tick freeze`**(它会冻死 `system.runInterval` 自身)。长度 `SUPER_FREEZE_TICKS = 8`（0.4 秒）。
2. **三气低血量分支**:在"释放被接受"那一刻按 `hp/maxHp ≤ 0.25` 取样并**锁定到结束**;随后按 `super_3_start → confirm → chain → (finish | low_finish)` 分段编排,命中时配对播 `*_victim`。阈值 `SUPER_3_LOW_HEALTH_RATIO = 0.25`。
3. **KO 慢放 + 特殊运镜**:新增 `"ko"` 阶段——双方锁输入 → 败者特写机位(`setCamera("minecraft:free", …OutCubic)` + `setFov(38)`)→ 白闪 → 震屏 → 停顿 `KO_PHASE_TICKS = 34` → 再接原有胜利动画。ScriptAPI 无时间缩放 API,故"突慢"由**逻辑停顿 + 运镜**近似。
4. **逐招真帧数据已接线**:27 段攻击用 `src/data/chunye.combat.ts` 的 `activeGameTicks`。**实测约束**:轻攻击 `attack_stand_light` 真帧 active 是作者 tick `[3,5)`,折算到 20tps **只有 1 个游戏 tick**,故按 `ACTIVE_WINDOW_MIN_TICKS = 2` 放宽(实际窗口 = 起手后第 2~3 tick);大招/发波/投技没有帧数据,走 `activeStart/activeEnd` 比例兜底。
5. **三段连打**:同一攻击键在 `CHAIN_WINDOW_TICKS = 28` 内再按 → 依次 `attack_{stance}_{kind}` / `_2` / `_3`;第 4 次按或窗口过期回到第一段;换招或非攻击键清空;受击与回合开始清空。状态按实体隔离(WeakMap),并用 `hasClip` 兜底。**静态校验:9 组 × 3 段 = 27 个连段动画名全部可解析**。
   - ⚠ **已知限制**:窗口从**起手**算,可用余量 = `CHAIN_WINDOW_TICKS − 招式时长`(轻击 23 / 重击 17 / `_3` 重击 15 tick);忙碌期被拒的按键会进 **`INPUT_BUFFER_TICKS = 8` 的输入缓冲**,硬直一结束自动起手(只保留最新一次按键)。
   - ⚠ **连段不区分站姿**:只记按键槽,因此"空中轻击起手 → 落地后 18 tick 内再按轻击"会接到地面的 `_2`。资产本身按 stand/crouch/air 分组,严格说不该跨组;待实机确认后再决定是否加站姿判定。

**尚未实现(按依赖顺序排)**

6. **取消系统 / 发波飞行物实体**:投技抓取、受击倒地、拆投和空振收招已接入；站立波的叶流仍是表现粒子，命中由服务端共享距离/高度窗口判定，尚未改成可被逐格碰撞的真实飞行物实体。

8. **场地**:在模板维度搭 1v1 擂台并回填 `src/config.ts` 坐标(不建场地无法开打)。

## 场地制作(首次运行前必做)

**推荐:用自带造场命令,一条命令搞定**

1. 部署后 `/reload`;
2. `/bearcade:tmp tp allstars` 进入模板维度;
3. **`/bearcade:allstars_buildmap`** —— 生成擂台(地板/净空/四周屏障/双方起始位标记)+ 准备台;
4. `/bearcade:tmp ap allstars` 应用到全部 8 个房间。

尺寸由 [combat-config.ts](src/combat-config.ts) 的 `ARENA_CENTER / ARENA_FLOOR_Y / ARENA_HALF_WIDTH` 与 [map.ts](src/map.ts) 的 `ARENA_HALF_DEPTH / ARENA_WALL_HEIGHT / ARENA_HEADROOM` 决定;**改尺寸后要同步 [config.ts](src/config.ts) 的 `TEMPLATE_FROM/TO`、`ROOM_COPY_ORIGIN`、`TICKING_*`**(否则 `tmp ap` 会漏掉一部分场地)。

**手动:想自己搭更精细的场地**

1. `/bearcade:tmp tp allstars` 进模板维度,手工搭建;
2. `/bearcade:tmp sz allstars` 用表单框定捕获范围;
3. 回填 `src/config.ts` 的坐标(`TEMPLATE_FROM/TO`、`ROOM_COPY_ORIGIN`、`PREP_SPAWN`、`TICKING_*`、`START_POSITIONS`);
4. `/bearcade:tmp ap allstars` 应用。
